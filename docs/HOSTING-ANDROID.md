# استقرار دائمی و اندروید

## وضعیت واقعی این نسخه

- پایشگر زمان‌بندی‌شده کارلنسر پیاده‌سازی شده، اما در محیط Arena درخواست مستقیم HTTPS به کارلنسر با خطای شبکه روبه‌رو شد. ابزار مرور صفحه عمومی `/search` را خواند؛ این به معنی اتصال موفق خود اپ نیست.
- parser علاوه بر تست‌های مصنوعی، در GitHub Actions با HTML زنده کارلنسر آزمایش شد و ۲۴ کارت پروژه استخراج کرد. این آزمون، موفقیت اتصال و استخراج در همان زمان و محیط را تأیید می‌کند، نه دقت کامل همه فیلدها یا دسترسی از هر میزبان. تغییر ساختار، صفحه خالی یا نیاز به JavaScript خطای آشکار می‌دهد، نه صفر آگهی یا موفقیت ساختگی.
- فقط اولین صفحه عمومی بررسی می‌شود؛ ممکن است پروژه‌های بین دو نوبت از صفحه خارج شوند. پوشش کامل همه آگهی‌ها تضمین نشده است.
- حساب کارلنسر برای این پایشگر استفاده نمی‌شود. ورود، پیشنهاد و تحویل در خود سایت انجام می‌شود. در 401/403/429 یا redirect توقف همان نوبت و گزارش خطا داریم؛ هیچ تلاش برای دور زدن محدودیت وجود ندارد.
- `robots.txt` در هر نوبت بررسی می‌شود؛ مسیرهای خصوصی `/api` و `/panel` اصلاً فراخوانی نمی‌شوند. robots مجوز قراردادی نیست؛ شرایط سایت و محدودیت‌های جاری باید رعایت شوند. صفحات بررسی‌شده: `https://www.karlancer.com/search`، `/robots.txt` و `/terms`.
- زمان‌بندی در سرور مستقل از گوشی است. پیش‌نمایش موقت Arena به معنی میزبانی ۲۴ساعته نیست.

## میزبانی شخصی (یک نمونه سرور، نه چند replica)

نیاز: میزبان Linux با Docker Compose، دسترسی خروجی HTTPS به کارلنسر، یک دامنه با DNS متصل به میزبان و پورت‌های 80/443 باز. حافظه شروع پیشنهادی ۵۱۲ مگابایت تا ۱ گیگابایت است؛ قیمت میزبان و دامنه جدا انتخاب و پرداخت می‌شود. هنوز هیچ میزبان یا دامنه‌ای خریداری نشده است.

```sh
cp deploy/.env.example deploy/.env
# Fill deploy/.env on your own host, not in chat.
# Generate a random secret locally with:
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build
```

رمز فضای کاری حداقل ۱۶ کاراکتر و SESSION_SECRET حداقل ۳۲ کاراکتر باشد. برنامه در حالت میزبانی بدون آنها شروع نمی‌شود. پورت 8000 به بیرون منتشر نمی‌شود؛ Caddy TLS را مدیریت می‌کند. دامنه باید قابل صدور گواهی باشد. کاربر از صفحه ورود HTTPS وارد کارنما می‌شود؛ رمز کارنما مستقل از حساب سایت‌های فریلنسری است. نشست امضاشده HttpOnly، Secure و SameSite=Strict بعد از ۲۴ ساعت منقضی می‌شود. تغییر SESSION_SECRET همه نشست‌ها را باطل می‌کند. نمونه بدون TLS فقط برای توسعه محلی و بدون داده حساس است.

داده‌ها در volume `app_data` باقی می‌مانند. `docker compose down -v` داده‌ها را حذف می‌کند؛ اجرا نکنید مگر حذف عمدی. به‌روزرسانی با همان فرمان up انجام می‌شود. از SQLite روی میزبان با ابزار backup خود SQLite و دسترسی محدود پشتیبان بگیرید. دیتابیس رمزگذاری نشده است؛ این سرویس تک‌کاربره است و ممیزی امنیتی مستقل ندارد.

پس از استقرار: وارد شوید، «بررسی اکنون» را بزنید؛ فقط نمایش **آخرین موفقیت** همراه با کارت‌های واقعی به معنی اتصال عملی است. خطا را با موفقیت اشتباه نگیرید. نرخ ساعتی پایشگر و توقف/فعال‌سازی از رابط قابل تنظیم است. فاصله پایش ۳۰ دقیقه است. درخواست دستی کمتر از یک دقیقه فاصله پذیرفته نمی‌شود. URLها نرمال و آگهی‌های قبلی تکرار نمی‌شوند؛ وضعیت سفارش قبلی با پایش بازنویسی نمی‌شود.

## اعلان وقتی برنامه بسته است

- با تنظیم SMTP_HOST، SMTP_USER، SMTP_PASSWORD و NOTIFY_EMAIL در فایل محیطی میزبان، ایمیل فرصت‌های تازه و اولین خطای پایش ارسال می‌شود. SMTP باید STARTTLS پشتیبانی کند؛ پورت پیش‌فرض 587 است. این اتصال در محیط فعلی با سرویس ایمیل واقعی آزمایش نشده است. نبود تنظیمات و خطای ارسال در داشبورد مشخص‌اند. این نسخه صف پایدار ارسال مجدد ایمیل ندارد.
- اعلان مرورگر فقط با صفحه باز کار می‌کند؛ PWA پوشِ پس‌زمینه ندارد.
- اپ بومی از WorkManager هر حدود ۳۰ دقیقه وضعیت میزبان را بررسی می‌کند؛ زمان دقیق تابع باتری و سیاست اندروید است. مجوز اعلان لازم است. انقضای نشست به شما اعلام می‌شود؛ واردشدن دوباره لازم است. اعلان دوره‌ای ممکن است همه رویدادهای بین دو بررسی را نبیند؛ برای رویدادهای تازه، ایمیل سمت سرور مناسب‌تر است. Worker فعلاً فقط آگهی تازه، خطای پایش و نیاز به ورود را اعلام می‌کند، نه پیام‌های حساب کارلنسر.

## نصب وب‌اپ روی اندروید — بدون APK

آدرس HTTPS کارنما را در Chrome اندروید **خارج از iframe پیش‌نمایش** باز کنید، وارد شوید و «نصب روی اندروید» یا منوی Chrome → Install app / Add to Home screen را انتخاب کنید. manifest، آیکن و service worker اضافه شده‌اند. این PWA با APK بومی متفاوت است. داده‌های خصوصی و HTML پروژه‌ها برای استفاده آفلاین cache نمی‌شوند؛ برای دیدن نتایج اتصال لازم است.

## ساخت APK بومی

پروژه `androidApp/` یک پوسته WebView برای میزبان HTTPS شما با WorkManager، دانلود خروجی‌ها و بازکردن لینک‌های بیرونی در مرورگر است. حساب کارلنسر در WebView داخلی وارد نمی‌شود. رابط و پردازش پروژه‌ها روی سرور است، نه یک موتور اجرای Arena روی اندروید.

نیاز: JDK 17، Android SDK 35 و Gradle 8.9 (یا Android Studio سازگار). ماژول قدیمی VPN از settings.gradle.kts کنار گذاشته شده، ولی فایل‌هایش حذف نشده‌اند.

```sh
gradle :androidApp:assembleDebug :androidApp:lintDebug --no-daemon
# androidApp/build/outputs/apk/debug/androidApp-debug.apk
```

Workflow `.github/workflows/android.yml` نیز برای ساخت و دریافت artifact به نام `karnama-android-debug` آماده است. در این محیط JDK/Android SDK نصب نبود؛ ساخت از طریق GitHub Actions انجام شد. **assembleDebug و lintDebug موفق شدند و ۱۷ تست بک‌اند نیز گذشتند. APK هنوز روی گوشی واقعی تست نشده است.** فایل ساخته‌شده از [artifact اجرای موفق](https://github.com/saeidkazemi1989-bot/filter/actions/runs/36343481613/artifacts/10940071640) قابل دریافت است؛ ZIP را باز کنید و androidApp-debug.apk را نصب کنید. برای دانلود artifact ممکن است ورود به حساب GitHub صاحب مخزن لازم باشد. artifact تاریخ انقضا دارد؛ بعداً می‌توان دوباره build گرفت. دانلود مستقیم artifact به محیط Arena به‌دلیل محدودیت دسترسی به میزبان ذخیره‌سازی GitHub ناموفق بود؛ بنابراین فایل باینری در workspace نیست. نسخه debug برای آزمایش شخصی است؛ انتشار عمومی نیازمند keystore امضای release، بررسی privacy و تست روی دستگاه است. keystore را در Git قرار ندهید.

در اولین اجرا آدرس ریشه HTTPS میزبان را وارد کنید؛ سپس با رمز کارنما وارد شوید. WebView مجوز دسترسی فایل، محتوای محلی، cleartext یا نادیده‌گرفتن خطای TLS ندارد. دانلودها در Downloads ثبت می‌شوند؛ ممکن است در نسخه‌های قدیمی‌تر اندروید محدودیت ذخیره‌سازی نیازمند تست تکمیلی باشد.

## هنوز خودکار نشده

ارسال پیشنهاد، شناسایی توافق از پیام‌های خصوصی، اجرای پروژه در Arena و تحویل نهایی به کارفرما. برای اینها اتصال رسمی و مجوز حساب لازم است. داشتن حساب کارلنسر به‌تنهایی دسترسی اجرایی به Arena ایجاد نمی‌کند. از کاربر رمز/OTP/کوکی در چت نخواهید. پرداخت و تحویل باید در خود کارلنسر و مطابق مقررات آن انجام شود.
